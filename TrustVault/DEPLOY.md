# Deploying TrustVault

Every step below is written for Windows. Nothing needs Linux, WSL or Docker.

## 1. Run it locally (Windows)

1. Install **Python 3.10+** from <https://www.python.org/downloads/windows/>. In the installer, tick **"Add python.exe to PATH"**.
2. Double-click **`setup.bat`**. This does three things:
   - creates `.venv` with the pinned dependencies;
   - creates `.env` with two fresh random secrets;
   - uses SQLite in `instance\`, so no database server is needed.
3. Double-click **`run.bat`**. It opens <http://127.0.0.1:8000>. Sign in with any account from the README.
4. Double-click **`test.bat`** to run the tests, and **`mutation-check.bat`** to remove each security check in turn and confirm a test fails every time.

To start again with fresh data, close `run.bat` and delete the `instance` folder. Keep `.env`.

## 2. Deploy to Render (free, about 10 minutes)

Render runs the Python web service **and** a managed PostgreSQL database from `render.yaml`.

**Before you start:**
- Install **Git for Windows**: <https://git-scm.com/download/win>.
- Have a GitHub account and a Render account (<https://render.com>, sign in with GitHub).

**Steps:**

1. On GitHub, create a new **empty public** repository, e.g. `trustvault`. Don't add a README or a .gitignore.
2. In this folder, open *Command Prompt* and run:
   ```bat
   publish-to-github.bat https://github.com/YOUR-NAME/trustvault.git
   ```
   This commits the folder, pushes it, and opens Render's *Deploy Blueprint* page for your repository.
   You can also do it by hand: Render dashboard → **New → Blueprint** → select the repository.
3. Render shows the two resources from `render.yaml`: the **trustvault** web service and the **trustvault-db** database. Click **Apply**.
4. Wait for the first deploy to finish (3–6 minutes). Your URL looks like `https://trustvault-xxxx.onrender.com`.
5. **Back up the master key now.**
   - In Render → trustvault → Environment, copy `TRUSTVAULT_MASTER_KEY` and `TRUSTVAULT_AUDIT_KEY` to a password manager.
   - If they are lost, the encrypted files and the audit chain can't be verified or recovered. That is what encryption means.
6. Verify the deployment from your PC:
   ```bat
   .venv\Scripts\python.exe scripts\live_check.py https://trustvault-xxxx.onrender.com
   ```
   All checks should say PASS. The first request can take about a minute while a free instance wakes up.
7. Sign in as `admin`, open **Oversight**, and look at the *Deployment check* card.
   - The recorded address should be **your** public IP.
   - If it shows a Render or Cloudflare proxy address instead, set `TRUSTVAULT_TRUST_PROXY_HOPS` to `2` in the Environment tab and check again.
   - Never set it higher than needed: every extra trusted hop lets a client forge its address.
8. Put the URL into `README.md`, the first line under the title, and commit.

### What `render.yaml` sets up

| Setting | Value | Why |
|---|---|---|
| `TRUSTVAULT_ENV` | `production` | Secure `__Host-` cookies and HSTS; refuses to start without secrets |
| `DATABASE_URL` | from `trustvault-db` | PostgreSQL on Render's private network; `ipAllowList: []` means no public access |
| `TRUSTVAULT_MASTER_KEY` / `TRUSTVAULT_AUDIT_KEY` | generated by Render | Random 256-bit values, generated once and never in Git |
| `TRUSTVAULT_DEMO_MODE` / `TRUSTVAULT_SEED_DEMO` | `true` | Seeds the README accounts and sample files on an empty database, and protects those accounts |
| `healthCheckPath` | `/healthz` | Render restarts the service if the database becomes unreachable |

### Free-tier limits to know

- **The web service sleeps after 15 minutes idle.** The next request wakes it in about a minute. Nothing is lost: all data is in PostgreSQL, not on the instance disk.
- **Render's free PostgreSQL expires 30 days after creation**, followed by a 14-day grace period. To keep the demo up longer, pick one:
  - Upgrade the database to a paid plan in Render. One click; no data loss.
  - Use any other PostgreSQL 13+ service, such as Neon or Supabase. Their free tiers don't expire.
    1. Create a database there.
    2. Copy its connection string, add `?sslmode=require` at the end if it isn't there, and paste it as `DATABASE_URL` in Render → Environment. This replaces the `fromDatabase` link.
    3. Redeploy. The schema and demo data are created automatically.

## 3. Other hosts

| Host | How |
|---|---|
| **Railway / Fly.io / Koyeb / Azure Container Apps** | Use the included `Dockerfile` (non-root, health check). Set `TRUSTVAULT_ENV=production`, `DATABASE_URL`, `TRUSTVAULT_MASTER_KEY`, `TRUSTVAULT_AUDIT_KEY` (two different random strings, 32+ characters), and `TRUSTVAULT_TRUST_PROXY_HOPS=1`. |
| **Heroku-style buildpacks** | The `Procfile` runs `python -m trustvault serve --port $PORT`. |
| **Windows Server / IIS** | Run `python -m trustvault serve --host 127.0.0.1 --port 8000` as a service (e.g. with NSSM), with IIS or another reverse proxy terminating HTTPS in front. Set `TRUSTVAULT_TRUST_PROXY_HOPS=1`. |
| **Netlify / Vercel / GitHub Pages** | **Not suitable.** These host static sites and short-lived functions. TrustVault needs a long-running server that holds the decryption key and makes every authorisation decision, plus a database. Putting a static front end there and the API elsewhere would add a cross-origin hop and weaken the CSRF and Origin protections for no benefit. |

Generate secrets on Windows with:

```bat
.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 4. Operating it

- **Verify the audit chain:** use the *Audit trail → Verify integrity* button, `POST /api/v1/admin/audit/verify`, or `python -m trustvault verify-audit`. The last exits with code 2 if the chain is broken.
- **Second copy of the audit:** every event is printed as one JSON line to the service log. In Render, open **Logs** and search for `"audit"`. Compare the latest `event_hash` with the head hash shown by *Verify*.
- **Turn off demo data:** set `TRUSTVAULT_SEED_DEMO=false` and `TRUSTVAULT_DEMO_MODE=false` before the first start on a new database.
- **Tests against PostgreSQL:**
  ```bat
  set TEST_DATABASE_URL=postgresql://user:pass@host:5432/emptydb
  test.bat
  ```
  The tests **drop and recreate the `public` schema** of that database, so never point them at real data.
